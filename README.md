# K-Scene Archive

외국인 대학생이 팀별로 K-콘텐츠 장면을 분석하고, 표현 선택 퀴즈와 플립 카드로 공유하는 한국어 학습 아카이브입니다. 프런트엔드는 HTML·CSS·Vanilla JavaScript, 서버는 Google Apps Script, 저장소는 Google Sheets를 사용합니다. 유료 서비스, AI API, 별도 운영 서버는 사용하지 않습니다.

## 구현한 기능

- 전체 화면에서도 **팀별 구획**을 유지하는 반응형 갤러리: 공개 카드 수, 팀 탭, 제목·태그 검색, 태그 필터, 최신 등록순·제목순 정렬.
- YouTube 일반·Shorts·단축 URL, 시작 시간(`t=90`, `t=1m30s`, `start=90`), 썸네일, 임베드, 항상 접근할 수 있는 원본 영상 버튼.
- 답안 선택 후 **서버 판정 → 정답·해설·7개 분석 영역 공개**. 오답도 분석 열람 가능. 명시적인 뒤집기 버튼, 앞면으로 돌아가기, 긴 분석 스크롤.
- 팀 작업실: 신규 작성, 부분 임시저장, 편집, 미리보기, 바로 공개, 팀 전용 코멘트 확인, 공개 후 수정. 작성 중인 자기 팀 카드 삭제.
- 교수자 관리: 전체·팀·상태 필터, 카드 상세 확인, 작성 팀 전용 비공개 코멘트 저장·변경·삭제, 보관·해제, 팀 추가·명칭·소개·번호·활성 여부·편집 코드 변경, 관리자 코드 변경.
- 서버 권한 검사, 팀별 분리, 솔트 해시, 6시간 세션, 로그인 실패 제한, LockService 잠금, 버전 충돌 감지, 사용자 텍스트의 안전한 출력과 시트 수식 주입 방지.
- 키보드 포커스·Escape 모달 닫기, 모션 감소 설정, 모바일 탭 스크롤, 저장 중 버튼 잠금과 한국어 오류 안내.
- 백엔드 없이 갤러리·퀴즈를 체험할 수 있는 별도 로컬 미리보기, 2개 팀의 가상 상황 4개.

학생 개인별 점수·랭킹·배지, 파일 업로드, 개인별 계정은 포함하지 않습니다. 공유 팀 코드 방식이므로 같은 팀 안에서 누가 수정했는지는 구분하지 않습니다.

## 파일 안내

| 파일 | 역할 | Apps Script에 추가 |

| `Samples.gs` | 가상 샘플 추가·제거 | 예 |

| `Styles.html` | CSS 변수·반응형·플립·접근성 | 예 |

| `appsscript.json` | V8·서울 시간대·시트 권한·웹 앱 설정 | 예 |
| `tools/preview.mjs` | 로컬 정적 미리보기 조립·개발용 HTTP 제공 | 아니요 |

`Index`는 HtmlService의 `include_()`로 `Styles`, `Scripts`를 포함합니다. Apps Script에는 HTML 파일을 세 개 각각 만들어야 합니다. 운영 HTML에 `Samples.gs`의 정답이나 로컬 미리보기 어댑터를 포함하지 않습니다.

## 먼저 화면만 살펴보기

로컬 미리보기에는 Google 계정, 로그인 코드, Sheets가 필요하지 않습니다. Node.js 20 이상을 사용합니다. Node는 **개발 미리보기와 테스트 전용**이며 실제 배포 서버가 아닙니다.

```bash
cd /workspace/K-Scene-Archive
node tools/preview.mjs --build
```

`.preview/index.html`이 생성됩니다. 일반 개인 PC에서는 이 파일을 브라우저로 열 수 있습니다. 파일 접근을 제한하는 환경에서는 다음 개발 서버를 사용합니다.

```bash
node tools/preview.mjs
```

기본 포트는 `4173`이고 `PORT` 환경 변수로 바꿀 수 있습니다. 서버는 로컬 루프백에만 바인딩합니다. 클라우드 온보딩 화면에서는 이 주소의 외부 미리보기를 제공하지 않으며 내부 검증용으로 사용합니다.

**미리보기에서 가능한 것:** 팀별 보기·검색·태그·퀴즈·앞뒤 전환·모바일 레이아웃. **불가능한 것:** 로그인·저장·코멘트. 미리보기 코드에는 가상 정답이 들어 있으므로 실제 평가나 수업용 배포에 사용하지 마세요. 실제 앱은 아래 절차로 배포해야 합니다.

샘플은 실제 K-콘텐츠 담화 분석이 아닌 가상 상황입니다. 연결한 YouTube 영상은 플레이어 확인용이며 작성된 대사와 관계가 없습니다. 영상 삭제·지역 제한·임베드 제한이 발생할 수 있습니다. 실제 수업에서는 교체해 주세요.

## 초보자를 위한 실제 배포: 처음부터 끝까지

### 1. Google Sheets 파일 만들기

1. 교수자 Google 계정으로 Google Drive를 엽니다.
2. **새로 만들기 → Google 스프레드시트**를 선택합니다.
3. 이름을 `K-Scene Archive 데이터`처럼 알아보기 쉽게 바꿉니다.
4. 주소가 `https://docs.google.com/spreadsheets/d/긴문자열/edit`라면 `/d/`와 `/edit` 사이가 **스프레드시트 ID**입니다. 복사해 보관합니다.
5. 학생에게 이 파일을 공유하지 않습니다. 팀 코드를 사용해 웹에서만 작성하게 할 것입니다.
6. 기본 `시트1`은 그대로 두어도 됩니다. 초기화 함수가 `Teams`, `Cards`를 자동 생성합니다.

### 2. 독립형 Apps Script 프로젝트 만들기

1. 같은 교수자 계정으로 [Google Apps Script](https://script.google.com/)에 접속합니다.
2. **새 프로젝트**를 선택합니다. 스프레드시트의 확장 프로그램 메뉴 대신 독립 프로젝트로 만들어도 작동합니다.
3. 프로젝트 이름을 `K-Scene Archive`로 바꿉니다.
4. 처음 생성된 `Code.gs` 내용을 이 저장소의 `Code.gs` 전체 내용으로 교체합니다.

### 3. 파일을 각각 추가하기

왼쪽 **파일 옆 + → 스크립트**에서 `Auth`, `Sheets`, `Setup`, `Samples`를 추가하고 대응하는 `.gs` 파일 내용을 붙여 넣습니다. 편집기가 `.gs` 확장자를 자동으로 붙입니다.

**파일 옆 + → HTML**에서 `Index`, `Styles`, `Scripts`를 추가합니다. 각 파일에 대응하는 `.html` 전체 내용을 붙여 넣습니다. 이름의 대소문자도 동일해야 합니다. `Styles`와 `Scripts`는 CSS/JS 파일 형식이 아닌 **HTML 파일 형식**입니다. `<style>`, `<script>` 태그도 함께 복사합니다.

왼쪽 **프로젝트 설정(톱니바퀴)**에서 **편집기에 appsscript.json 매니페스트 파일 표시**를 켭니다. 파일 목록으로 돌아와 `appsscript.json`의 내용을 이 저장소 파일로 교체하고 저장합니다.

`tests`, `tools`, `.preview`, README는 Apps Script 파일로 추가하지 않습니다.

### 4. 스프레드시트 ID와 최초 코드 설정하기

**프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**에서 다음 세 항목을 등록합니다.

| 속성 이름 | 입력값 |
| --- | --- |
| `SPREADSHEET_ID` | 1단계에서 복사한 스프레드시트 ID. URL 전체가 아닙니다. |
| `ADMIN_SETUP_CODE` | 교수자가 만든 관리자 코드. 공백만이 아닌 5~15자. |
| `TEAM_SETUP_JSON` | 아래 구조의 JSON 배열. 팀별로 서로 다른 5~15자 코드를 정하세요. |

`TEAM_SETUP_JSON` 구조 예시입니다. 대문자 자리표시는 실제 새 코드로 **반드시 교체**하세요. 코드에는 비밀번호 관리자에서 생성한 5~15자 안에서 무작위 문자열을 권장합니다. 본인 Google 계정 비밀번호를 사용하지 마세요.

```json
[
  {"teamId":"team1","teamName":"말의 온도","editCode":"CHANGE_TEAM1"},
  {"teamId":"team2","teamName":"장면 수집가","editCode":"CHANGE_TEAM2"}
]
```

- 관리자와 모든 팀은 서로 다른 코드를 사용해야 합니다.
- 팀을 다섯 개 쓰려면 배열에 팀 다섯 개를 넣으면 됩니다. 번호는 배열 순서로 1부터 지정됩니다.
- 팀 ID는 중복 없이 영문·숫자·`_`·`-`로 1~40자입니다. 나중에 이름과 번호는 바꿀 수 있지만 ID는 바꾸지 않습니다.
- JSON의 큰따옴표·쉼표·대괄호를 그대로 지켜 주세요. 마지막 항목 뒤에 쉼표를 추가하지 않습니다.
- 코드를 GitHub나 HTML에 넣지 않습니다. `SPREADSHEET_ID`도 서버 설정에만 저장합니다.
- 프로젝트를 편집할 수 있는 사람은 서버 코드·속성·시트에 접근할 수 있습니다. 학생에게 프로젝트 편집 권한을 주지 마세요.

### 5. 데이터 시트 자동 초기화와 최초 권한 승인

1. 편집기로 돌아와 `Setup.gs`를 선택합니다.
2. 상단 함수 선택 목록에서 **`setupEnvironment`**를 선택합니다. 설치용 공개 이름이며 실제 초기화는 내부 `initialize_`로 위임합니다.
3. **실행**을 누릅니다. 최초에는 권한 검토가 나타납니다.
4. **권한 검토 → 교수자 계정 선택** 후 이 앱이 스프레드시트에 접근하는 것을 승인합니다. 승인 대상이 본인이 만든 프로젝트인지 확인하세요.
5. 개인 테스트 앱에 Google의 미확인 앱 경고가 나타날 수 있습니다. 본인이 작성한 프로젝트임을 확인한 뒤 계정·조직 정책이 허용하는 절차를 따르세요. 조직에서 승인을 차단하면 Workspace 관리자에게 문의해야 합니다.
6. 실행이 완료되면 스프레드시트에 `Teams`, `Cards` 시트와 헤더가 생성되었는지 확인합니다.
7. 실행 로그에서 초기화 완료를 확인합니다. 로그인 코드 원문은 출력하지 않습니다.
8. 스크립트 속성으로 돌아가면 `ADMIN_SETUP_CODE`, `TEAM_SETUP_JSON`은 삭제되고, 솔트·해시가 저장되어 있습니다. 코드는 안전한 곳에 별도로 보관해 주세요.

`initialize_`를 반복 실행하면 기존 데이터를 덮어쓰지 않고 중단합니다. **중간 실패** 시 시트에 일부 팀이 남을 수 있습니다. 로그와 데이터부터 확인하고, 최초 설치 중이었다면 부분 생성 데이터를 백업한 뒤 **새 빈 스프레드시트 ID**를 설정하여 다시 시작하세요. 학생 데이터를 삭제하거나 초기화 함수를 반복 실행해 해결하지 마세요.

내부 함수 이름 끝의 `_`는 웹의 `google.script.run` 호출을 차단합니다. 편집기 실행 메뉴에서는 `Setup.gs`의 `setupEnvironment`, `addSampleCards`, `removeSampleCards`, `recoverAdminCode`를 사용하세요. 이 진입점은 로그인한 실행 계정과 유효 실행 계정의 이메일이 일치할 때만 실행됩니다. 이를 위해 매니페스트에 `userinfo.email` 권한을 추가했습니다. 학생의 팀 코드 로그인에는 이메일을 사용하지 않습니다.

**상단이 `함수 없음`이라면:** `Setup.gs`에 파일 전체를 붙여 넣었는지 확인하고 저장(`Ctrl+S`/`⌘+S`)한 뒤 새로고침하세요. Markdown 코드 경계인 ``` 문자는 붙여 넣지 않습니다. 프로젝트의 다른 파일에 구문 오류가 있어도 함수 인식이 안 될 수 있으므로 저장 시 표시되는 파일명·줄 번호의 오류부터 확인합니다. `.gs` 파일에는 `<script>` 태그를 넣지 않으며 `Styles`, `Scripts`는 HTML 파일로 생성합니다.

### 6. 샘플 넣기·교체·제거

화면 검토가 필요하면 `Setup.gs`의 **`addSampleCards`**를 선택해 한 번 실행합니다. 활성 팀 두 개가 필요하며 앞의 두 팀에 2개씩, 총 4개가 **공개 상태**로 추가됩니다. 실제 수업 자료가 아니므로 수업 전에 지워 주세요.

**`removeSampleCards`**를 실행하면 설치 시 기록한 샘플 UUID에 해당하는 카드만 삭제합니다. 학생이 만든 카드는 보존합니다. 삭제는 되돌릴 수 없으므로 수정한 샘플 내용을 남기려면 먼저 시트를 백업하세요. 샘플 수정은 `Samples.gs`의 `sampleCards_()` 내용을 변경하고 기존 샘플 제거 후 다시 추가하면 됩니다. `DEMO_CARD_IDS` 속성을 수동으로 지우면 제거 대상을 추적할 수 없으므로 유지하세요.

팀 수·정보·코드는 실제 운영 시 교수자 웹 화면에서 관리할 수 있습니다. 시트에 해시 값을 직접 입력하지 마세요.

### 7. 웹 앱으로 배포하기

1. Apps Script 오른쪽 위 **배포 → 새 배포**를 누릅니다.
2. 유형 선택의 톱니바퀴에서 **웹 앱**을 선택합니다.
3. 설명에 `첫 수업용 배포`처럼 버전 설명을 적습니다.
4. **다음 사용자 인증 정보로 실행: 나(배포하는 교수자 계정)**를 선택합니다.
5. **액세스 권한이 있는 사용자**는 수업 환경에 맞게 선택합니다. 학생 이메일을 사용하지 않는 공유 코드 흐름에는 **모든 사용자(익명 포함)** 접근이 가능한 설정이 적합합니다. UI 표현은 계정 정책에 따라 다릅니다.
6. **배포**를 누르고 추가 권한 승인이 있으면 완료합니다.
7. 표시되는 **웹 앱 URL**을 복사합니다. 학생 공유용은 보통 `/exec`로 끝납니다. `/dev` 테스트 URL은 편집자용이며 학생 배포 주소가 아닙니다.

**실행 계정과 접근 권한의 차이**

- **실행 계정**은 누구의 권한으로 Sheets를 읽고 쓰는지 정합니다. 교수자로 실행해야 학생에게 원본 시트 권한을 주지 않고 저장할 수 있습니다.
- **접근 권한**은 누가 웹 페이지를 열 수 있는지 정합니다. 익명 접근을 허용하면 URL을 아는 사람은 공개 카드를 볼 수 있습니다. 편집·코멘트 작성은 여전히 서버의 팀/관리자 코드 인증을 통과해야 합니다.
- 수업 외 공개 열람을 원하지 않으면 학교 조직 내부 또는 Google 로그인 필요 설정을 선택하고 실제 학생 계정으로 접근 가능 여부를 확인하세요. 단, 같은 조직의 다른 사람까지 배포 정책 범위에 포함될 수 있습니다. 팀 코드는 공개 갤러리 열람을 제한하는 수단이 아닙니다.
- **접속 사용자로 실행**하면 학생마다 Google 승인과 시트 권한이 필요해질 수 있으므로 이 프로젝트의 기본 운영 방식과 맞지 않습니다.
- Workspace 관리자가 익명 배포를 금지한 경우 코드로 우회할 수 없습니다. 학교 정책이 허용하는 접근 설정을 사용해야 합니다.

`appsscript.json`의 기본 웹 앱 설정은 배포자 실행·익명 접근입니다. 최종 배포 창에서 실제 계정의 선택 사항과 정책을 확인하세요. 학생 이메일이 항상 제공된다고 가정하지 않습니다.

### 8. 첫 운영 확인 후 학생에게 공유하기

서로 다른 브라우저 또는 시크릿 창으로 다음을 **실제 배포에서** 확인하세요.

1. 로그아웃 상태에서 팀별 공개 카드와 썸네일이 보입니다.
2. 1팀 코드로 작업실에 로그인하고 새 카드를 부분 저장합니다.
3. 페이지를 새로고침하거나 다시 접속해 저장한 카드가 남아 있는지 확인합니다.
4. 필수 항목을 채우고 미리보기 후 **카드 공개**를 누릅니다. 교수자 승인 없이 갤러리에 바로 표시됩니다.
5. 교수자로 로그인해 **카드·코멘트 보기**를 열고 **작성 팀만 보는 교수자 코멘트**를 적어 저장합니다. 카드의 공개 상태는 바뀌지 않습니다.
6. 1팀 작업실의 목록과 카드 편집 화면에서 코멘트를 확인합니다. 공개 카드도 바로 수정할 수 있습니다.
7. **수정 내용 공개**를 눌러 수정 결과를 반영합니다. 다시 승인을 받을 필요가 없습니다.
8. 2팀으로 접속하면 1팀 작업실과 코멘트를 볼 수 없어야 합니다. 공개 갤러리와 퀴즈의 정답·분석 응답에도 교수자 코멘트가 포함되지 않습니다.
9. 공개를 잠시 중단하려면 작성 팀이 **비공개로 저장**합니다. 이때 카드가 갤러리에서 숨겨지고 작성 중 상태가 됩니다. 다시 **카드 공개**하면 공개됩니다.
10. 실제 영상 재생과 원본 열기, 오답·정답, 카드 뒤집기·다시 보기, 휴대폰 화면을 확인합니다.

완료 후 `/exec` URL과 **각 팀에 해당하는 코드만** LMS 등으로 전달합니다. 관리자 코드·원본 시트·Apps Script 편집 URL은 학생에게 공유하지 않습니다.

### 9. 교수자 코멘트와 상태 사용법

| 현재 상태 | 작성 팀 | 교수자 |
| --- | --- | --- |
| 작성 중 (`draft`) | 편집·임시저장·바로 공개·삭제 | 코멘트·보관 |
| 공개 (`published`) | 편집·수정 내용 공개·비공개로 저장 | 코멘트·비공개 보관 |
| 보관 (`archived`) | 내용과 코멘트 읽기 | 코멘트·보관 해제 |
| 이전 제출 (`submitted`) / 이전 수정 요청 (`revision`) | 이전 버전의 상태. 편집 후 바로 공개 가능 | 코멘트·보관 |

**교수자 승인 절차는 없습니다.** 코멘트 저장은 공개·비공개 상태를 바꾸지 않습니다. 교수자와 카드 작성 팀만 코멘트를 확인합니다. 교수자는 코멘트를 수정하거나 입력란을 비워 저장해 삭제할 수 있습니다. 현재는 카드마다 최신 코멘트 한 개를 저장하며 댓글 이력·개별 알림은 제공하지 않습니다. 팀원은 작업실 목록을 새로고침하거나 카드를 다시 열어 새 코멘트를 확인합니다.

작성 팀의 공개 카드 수정은 **수정 내용 공개**를 눌렀을 때 갤러리에 반영됩니다. 편집 중인 입력은 저장 전까지 서버 내용에 영향을 주지 않습니다. 공개 중인 카드의 미완성 내용을 저장하려면 **비공개로 저장**을 사용합니다. 별도 공개본과 작업본을 동시에 저장하는 구조는 아닙니다.

교수자의 **비공개 보관**은 카드를 갤러리에서 숨기고 팀 편집을 중단합니다. **보관 해제**하면 작성 중으로 돌아가며 팀이 확인 후 다시 공개합니다. 보관·해제는 코멘트를 지우거나 변경하지 않습니다.

코멘트 저장도 카드 버전을 갱신합니다. 팀원이 편집하는 동안 교수자가 코멘트를 남기면 충돌 안내가 나올 수 있습니다. 입력 내용을 복사하고 목록에서 최신 카드를 다시 열어 반영하세요. 학생은 서버에 보낸 데이터로 교수자 코멘트를 덮어쓸 수 없습니다.

**팀 정보**에서 팀명·소개·번호·활성 여부를 바꾸거나 새 팀을 추가합니다. 번호는 표시 순서이자 화면의 `1팀`, `2팀` 표시에 사용하므로 중복 없이 관리해 주세요. 비활성화는 데이터를 지우지 않으며 해당 팀 로그인과 갤러리 공개를 중단합니다. 활성화하면 기존 공개 카드가 다시 표시됩니다.

편집 코드와 관리자 코드의 신규·변경 값은 모두 5~15자이며 서로 달라야 합니다. 코드 변경 시 해당 계정의 기존 세션은 만료됩니다.

관리자 코드를 잊었다면 **프로젝트 소유자**가 스크립트 속성 `ADMIN_SETUP_CODE`에 새 코드를 추가하고 편집기에서 **`recoverAdminCode`**를 실행합니다. 새 코드는 팀 코드와 달라야 하며 실행 후 원문 속성은 삭제됩니다. 시트 데이터는 유지됩니다.

### 10. 코드 수정 후 배포 버전 업데이트

1. GitHub와 현재 시트를 먼저 백업합니다.
2. Apps Script 편집기에서 변경한 파일을 갱신하고 저장합니다.
3. 테스트 배포로 해당 기능을 점검합니다. 단순 저장만으로 기존 학생용 배포가 업데이트되는 것은 아닙니다.
4. **배포 → 배포 관리 → 기존 배포 선택 → 수정(연필)**을 누릅니다.
5. 버전을 **새 버전**으로 바꾸고 설명을 적은 뒤 배포합니다.
6. 기존 배포를 갱신하면 학생용 URL을 유지할 수 있습니다. 별도의 새 배포를 만들었다면 새 URL을 공유해야 합니다.
7. 학생 브라우저에서 새로고침하고 정상 동작을 확인합니다. 함수 인자나 데이터 구조가 달라졌다면 오래 열린 탭도 다시 열도록 안내합니다.

헤더와 필드 이름을 바꾸는 변경은 데이터 마이그레이션이 필요합니다. 이 버전의 초기화 함수는 기존 시트 구조를 자동 변경하지 않습니다.

### 11. 오류와 로그 확인

Apps Script 왼쪽 **실행** 메뉴에서 해당 시간의 실행을 선택해 완료·실패·소요 시간을 확인합니다. 편집기에서 직접 실행한 초기화 로그는 하단 **실행 로그**에서도 볼 수 있습니다. 학생의 오류 시간, 함수 이름, 화면 오류 문구를 함께 확인하세요. 인증 코드·세션 토큰·학생 작성 내용 전체를 로그나 공개 문의에 붙이지 마세요.

| 화면/증상 | 확인할 것 |
| --- | --- |
| 저장소 연결 실패 | `SPREADSHEET_ID`가 정확한지, 배포자 계정이 시트를 편집할 수 있는지, 파일이 삭제되지 않았는지 |
| 데이터 초기화 필요 | `initialize_`가 성공했는지, `Teams`와 `Cards` 이름이 정확한지 |
| 시트 열 구조 오류 | 자동 생성된 헤더를 변경·이동·삭제하지 않았는지. 백업본과 비교하고 임의로 덮어쓰지 않기 |
| 로그인이 안 됨 | 팀 선택, 대소문자·공백, 팀 활성 여부, 코드 재발급 여부 |
| 시도 횟수 초과 | **계정(팀/관리자) 단위로 15분에 실패 5회** 제한. 같은 팀도 영향을 받으므로 기다린 뒤 정확한 코드 사용 |
| 로그인 만료 | 6시간 만료 또는 코드 변경·팀 비활성화. 입력 내용을 복사해 보관하고 다시 로그인 |
| 다른 사용자가 먼저 수정 | 버전 충돌. 현재 입력을 별도로 복사하고 목록에서 최신 카드를 열어 필요한 내용을 다시 반영 |
| 응답 지연·연결 끊김 | 자동 재시도하지 않습니다. 이미 저장되었을 수 있으므로 입력을 복사하고 목록 새로고침으로 결과부터 확인 |
| 다수 접속·서버 오류 | Apps Script 실행/읽기·쓰기/Properties 용량 등 계정 할당량, 서비스 장애 확인. 잠시 후 재시도 |
| 영상이 재생 안 됨 | 저작권·연령·지역·임베드 제한 또는 삭제 가능. **원본 영상 열기** 사용 후 필요 시 허용 영상으로 교체 |
| 학생이 배포에 접근 못 함 | `/exec` 주소인지, 실행 계정과 접근 범위, 학교 Workspace 정책 확인 |

YouTube 무료 IFrame API가 로드되면 오류 이벤트에서 플레이어를 원본 열기 안내로 대체합니다. API 스크립트 자체가 학교 네트워크나 브라우저에서 차단되면 오류 감지가 불가능하므로 **원본 열기 버튼도 항상 제공**합니다. 이 기능에는 API 키가 필요하지 않습니다. 실제 영상 재생 가능 여부는 선택한 영상·브라우저·학교 네트워크에서 확인해야 합니다.

시트 잠금은 이 Apps Script의 요청끼리 조정합니다. 교수자가 Sheets 원본을 동시에 직접 편집하면 충돌 검사를 우회할 수 있습니다. 운영 중 카드 내용은 웹 앱에서 수정하고, 데이터 백업·열 구조 점검 외에는 원본 수정을 피하세요.

### 12. GitHub에 소스 백업하기

GitHub 저장소 `circleizt-sketch/K-Scene-Archive`에는 소스 파일과 문서·테스트만 보관합니다. 실제 로그인 코드, 스크립트 속성, 세션, 학생 데이터가 든 시트, Google 인증 파일은 올리지 않습니다.

Git을 사용하는 경우 저장소 폴더에서:

```bash
git status
git add Code.gs Auth.gs Sheets.gs Setup.gs Samples.gs Index.html Styles.html Scripts.html appsscript.json README.md VALIDATION.md .gitignore .claspignore tools tests
git commit -m "Build K-Scene Archive learning app"
```

그 후 GitHub 계정의 권한이 있는 환경에서 원격 브랜치로 `git push`합니다. 현재 커밋과 원격 업로드 상태는 저장소의 Git 기록에서 확인할 수 있습니다. 현재 저장소가 최초 커밋 전이라면 브랜치 이름을 확인하고 GitHub에서 사용할 기본 브랜치를 정하세요.

Git 사용이 어려우면 GitHub 저장소 페이지의 **Add file → Upload files**로 위 소스 파일을 올릴 수 있습니다. Apps Script에서 직접 수정한 경우에도 같은 파일을 내려받거나 복사해 GitHub 쪽과 맞춰 주세요.

선택적으로 Google의 `clasp` 도구를 사용할 수 있습니다. 이 저장소의 `.claspignore`는 운영 `.gs`, 지정한 HTML 3개, 매니페스트만 업로드하도록 제한합니다. 로그인·프로젝트 연결은 본인 계정에서 진행해야 하며 이 프로젝트의 필수 설치 절차는 아닙니다. `.clasp.json`은 Git에서 제외합니다.

## 데이터 구조와 보안 동작

`Teams` 열:

```text
teamId, teamName, teamDescription, sortOrder, active, editCodeHash, editCodeSalt
```

`Cards` 열:

```text
cardId, teamId, title, contentTitle, videoUrl, description, tagsJson,
context, relationship, mainExpression, discourseAnalysis, nonverbalAnalysis,
culturalContext, learningPoint, quizQuestion, quizOptionsJson, correctChoiceId,
quizExplanation, status, teacherFeedback, version, createdAt, updatedAt, publishedAt
```

- 카드 ID는 서버 생성 UUID, 날짜는 UTC ISO 8601 문자열, 화면 표시 날짜는 서울 시간대입니다.
- 태그·선택지는 JSON 문자열로 저장하고 웹 응답에서 배열로 복원합니다.
- `getGallery()`는 공개·활성 팀 카드의 명시적 앞면 필드만 반환합니다. 상황적 배경은 학생이 작성한 **장면 소개**로 제공하며, 분석의 상황 맥락·관계 필드는 정답 제출 전 제공하지 않습니다.
- `submitQuiz(cardId, choiceId, version)`는 현재 공개 여부·버전·선택지 유효성을 서버에서 확인한 뒤 정답과 분석을 반환하며 교수자 코멘트는 제외합니다. 개별 점수는 저장하지 않습니다.
- 팀 작업실에서는 자기 팀만, 관리자에서는 전체 카드의 정답·분석을 확인할 수 있습니다.
- 코드 검증은 팀마다 별도 무작위 솔트와 1,000회 SHA-256 해시를 사용합니다. 공유 코드 특성상 강한 무작위 코드를 선택하고 주기적으로 교체하세요. 개인별 계정 보안이나 메모리 집약적 비밀번호 KDF와 동일한 보장으로 보지 않습니다.
- 세션은 UUID 두 개로 만든 토큰이고 서버에는 토큰 해시·역할·만료를 저장합니다. 브라우저는 `sessionStorage`를 사용합니다. 탭을 닫거나 6시간이 지나면 재로그인이 필요할 수 있습니다.
- 세션 최대 400개, 팀 최대 50개입니다. 만료 세션과 실패 기록은 로그인 시 정리합니다. 수업 규모에 맞춰 Apps Script 할당량을 확인하세요.
- 모든 변경은 서버 권한 확인 및 동일 ScriptLock 안에서 처리합니다. 카드 편집·코멘트·삭제는 현재 `version` 일치가 필수입니다. 보관 카드의 팀 편집 등 허용되지 않은 상태 전이는 차단합니다.
- 시트에서 `=`, `+`, `-`, `@`, 작은따옴표, 제로폭 문자로 시작하는 사용자 문자열은 제로폭 문자로 이스케이프해 수식 실행을 막고 읽을 때 원문을 복원합니다. 원본 시트에서 이 문자를 제거하지 마세요.
- 웹은 입력을 HTML로 실행하지 않고 DOM 텍스트로 출력합니다. 영상 주소는 허용 도메인·ID·시간 검증 후 새 임베드 URL을 생성합니다.
- 시트 원본은 신뢰할 수 있는 교수자만 접근합니다. 시트에 정답과 분석이 저장되므로 학생에게 원본 권한을 주면 정답 보호가 성립하지 않습니다.
- 이 버전은 수업 규모용입니다. 요청마다 시트를 읽으며 대규모 공개 트래픽이나 정교한 공격 대응을 위한 별도 서버를 제공하지 않습니다.

## 개발 및 검증 명령

별도 패키지 설치 없이 서버 모의 테스트를 실행할 수 있습니다.

```bash
node tests/server.test.mjs
```

Google의 SpreadsheetApp·PropertiesService·LockService·Utilities를 로컬 메모리 구현으로 대체합니다. 12개 테스트가 인증·직접 공개·코멘트 비공개·권한·충돌·입력 검증·샘플 제거·연결 오류를 확인합니다. **실제 Google Sheets API 호출이나 배포 권한을 검증한 것은 아닙니다.**

Chromium UI 통합 테스트는 개발용 Playwright와 Chromium이 있는 환경에서 실행합니다. 이 의존성은 실제 배포에는 필요 없습니다.

```bash
# 개인 PC에 Playwright가 없다면 로컬 개발용으로만 설치
npm install --no-save --package-lock=false playwright@1.62.1
# Chromium 위치가 다르면 CHROMIUM_PATH로 지정
node tools/preview.mjs --build
CHROMIUM_PATH=/usr/bin/chromium node tests/browser.test.mjs
```

테스트는 임시 로컬 HTTP 서버와 브라우저를 실행하고 종료합니다. `.test-results`에 화면을 저장합니다. 외부 영상 요청은 차단하고, 썸네일은 첫 주소 실패·대체 주소 성공을 모의 이미지 응답으로 검증합니다. 운영 프런트엔드의 `google.script.run`은 같은 서버 모의 구현에 연결하여 저장·재접속·직접 공개·팀 전용 코멘트 흐름을 확인합니다. 실제 영상 재생 성공을 의미하지 않습니다.

현재 검증 결과와 남은 실배포 점검은 [VALIDATION.md](VALIDATION.md)를 참고하세요.

## 코드 길이 변경 적용

관리자와 팀의 신규·변경 코드는 모두 **5~15자**입니다. 기존 코드의 해시는 그대로 보존하므로 길이가 더 긴 기존 코드로도 로그인할 수 있으며, 로그인 후 새 코드로 변경하면 새 규칙이 적용됩니다. 이미 초기화한 환경은 `TEAM_SETUP_JSON` 수정으로 팀 코드가 바뀌지 않습니다. 교수자 화면에서 각 팀의 편집 코드를 저장하세요.

기존 배포에 적용하려면 `Auth.gs`, `Scripts.html` 전체 내용을 교체하고 저장한 뒤 **배포 → 배포 관리 → 수정 → 새 버전 → 배포**로 갱신합니다. 웹 페이지를 새로고침하고 교수자 관리 화면에서 코드를 변경합니다. 초기화와 시트 데이터 삭제는 필요 없습니다.

## 썸네일·직접 공개·비공개 코멘트 변경 적용

기존 운영 프로젝트에서는 `Code.gs`, `Sheets.gs`, `Scripts.html`, `Styles.html` 4개를 전체 교체하고 **새 버전으로 배포**합니다. 시트 헤더·데이터 구조는 그대로 사용하며 초기화나 데이터 삭제는 하지 않습니다. 이전 제출·수정 요청 상태는 자동 공개하지 않습니다. 작성 팀이 카드를 열어 `카드 공개`를 선택하면 바로 공개됩니다. 기존 교수자 피드백은 같은 `teacherFeedback` 열을 사용하므로 새 비공개 코멘트 화면에서 계속 볼 수 있습니다.

썸네일 대체 배경이 정상 이미지를 덮던 CSS 배치 문제를 수정했습니다. YouTube ID를 추출해 공식 썸네일을 표시하고, 이미지 로드에 실패하면 다른 공식 주소를 시도합니다. 영상 삭제·연령 제한·학교 네트워크의 이미지 차단 등으로 모든 주소가 실패하면 대체 배경을 유지합니다. 이 경우 영상을 열어 원본 링크로 확인하세요.
